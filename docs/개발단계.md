# 개발 단계

한 번에 다 만들지 않는다. **한 단계 = 그 화면에 필요한 기반 + 화면 1개 정도.**

## 단계마다 지키는 것

- 각 커밋이 단독으로 `npm run build` · `npm run typecheck` · `npm run lint` 를 통과한다
- 화면은 **320 / 375 / 768 / 1440** 에서 실제로 렌더링해 본다
- `docs/디자인품질기준.md` 0장 체크리스트가 "끝났다"의 정의다
- 단계 끝에 `front-review` 검수 → 치명·경고를 고친 뒤 다음 단계로
- 커밋은 **완결된 기능 묶음**(에이전트 1회당 3~6개), 푸시는 **작업 끝에 한 번** (2026-09-24 변경)

---

## 단계 0 — 환경설정 ✅

Vite + React + TypeScript, 라우팅 9개 자리표시자, 디자인 토큰, TanStack Query.

## 단계 1 — 인증 기반 + 목록 화면(SCR-01) ✅ 구현 완료 · 검수 대기

모든 화면이 기대는 기반을 먼저 만들고, 그 위에 첫 화면을 올린다.

| | 내용 |
|---|---|
| API 레이어 | HTTP 클라이언트(`credentials: 'include'`, 오류에 `status`·`code`), 백엔드 DTO → TS 타입, 게시글 목록 API |
| 인증 | 액세스 토큰 **메모리** 저장, 401 재발급 **단일 비행**, 앱 시작 시 재발급 시도, 인증 Context(Context + useReducer) |
| 공통 UI | 유형·상태 배지, 버튼, 스켈레톤, 빈 상태, 오류 상태 |
| 레이아웃 | 헤더 — 로고 · 글 올리기 · 로그인/내 정보 |
| SCR-01 | 카드 그리드, 검색, 필터(유형·카테고리·상태·지역·기간), 활성 필터 칩, 페이지, 네 가지 상태 |

**만들지 않는 것** : 로그인 화면(헤더의 로그인 버튼은 `/login` 자리표시자로 간다), 온보딩.

**구현하면서 바뀐 판단** (2026-09-24)
- 모바일(768 미만)은 **1열 가로형 카드**. 목록 API에 썸네일이 없어 2열이면 카드 대부분을 자리표시자가 차지한다. 백엔드 썸네일이 붙으면 재검토
- 1024 이상은 필터를 **왼쪽 열에 펼친다.** 드롭다운 다섯 개에 선택지를 숨기는 것보다 다 보이는 편이 낫다
- [더 보기] 대신 **페이지 이동**, 우하단 고정 버튼 대신 **헤더의 [+ 글 올리기]**
- 남은 일 : `front-review` 검수 → 치명·경고 수정

## 단계 2 — 로그인 · 회원가입(SCR-05, SCR-06) + 온보딩 1층

## 단계 3 — 상세(SCR-03)

상태 변경, 삭제(결과 고지 다이얼로그), 댓글 읽기. 댓글 쓰기·더 보기는 백엔드 `[5.1]` 머지 후.

## 단계 4 — 등록 · 수정(SCR-02, SCR-04)

이미지 업로드 전 축소(긴 변 2048px, JPEG 0.85), 5장 제한, 수정 시 이미지 교체 규칙 고지.

## 단계 5 — 내 정보(SCR-08) · 마이페이지(SCR-07) · 404(SCR-09)

마이페이지는 백엔드 `[6.1]`(`GET /api/members/me/posts`) 이후.

## 단계 6 — 마무리

온보딩 2층(맥락 안내), `docs/보안명세서.md` 9장 배포 전 점검, 전 화면 재검수.
