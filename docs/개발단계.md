# 개발 단계

한 번에 다 만들지 않는다. **한 단계 = 그 화면에 필요한 기반 + 화면 1개 정도.**

## 단계마다 지키는 것

- 각 커밋이 단독으로 `npm run build` · `npm run typecheck` · `npm run lint` 를 통과한다
- 화면은 **320 / 375 / 768 / 1440** 에서 실제로 렌더링해 본다
- `docs/디자인품질기준.md` 0장 체크리스트가 "끝났다"의 정의다
- 단계 끝에 `front-review` 검수 → 치명·경고를 고친 뒤 다음 단계로
- 커밋은 **완결된 기능 묶음**(에이전트 1회당 2~3개 — 예: 코드 묶음 하나 + 문서 하나), 푸시는 **작업 끝에 한 번** (2026-09-25 변경)

---

## 단계 0 — 환경설정 ✅

Vite + React + TypeScript, 라우팅 9개 자리표시자, 디자인 토큰, TanStack Query.

## 단계 1 — 인증 기반 + 목록 화면(SCR-01) ✅ 재설계 완료 · 본인 확인 대기

모든 화면이 기대는 기반을 먼저 만들고, 그 위에 첫 화면을 올린다.

| | 내용 |
|---|---|
| API 레이어 | HTTP 클라이언트(`credentials: 'include'`, 오류에 `status`·`code`), 백엔드 DTO → TS 타입, 게시글 목록 API |
| 인증 | 액세스 토큰 **메모리** 저장, 401 재발급 **단일 비행**, 앱 시작 시 재발급 시도, 인증 Context(Context + useReducer) |
| 공통 UI | 유형·상태 배지, 버튼, 스켈레톤, 빈 상태, 오류 상태, 시트(좁은 화면 바텀 시트 · 넓은 화면 다이얼로그) |
| 레이아웃 | 헤더 — 로고 · 글 올리기 · 로그인/내 정보 |
| SCR-01 | 의도 선택(잃어버렸어요 · 주웠어요), 검색, 필터 칩 + 시트(카테고리·상태·장소·기간), 사진 피드, 페이지, 의도별 다음 행동, 네 가지 상태 |

**만들지 않는 것** : 로그인 화면(헤더의 로그인 버튼은 `/login` 자리표시자로 간다), 온보딩.

**구현하면서 바뀐 판단** (2026-09-24, 1차)
- [더 보기] 대신 **페이지 이동**, 우하단 고정 버튼 대신 **헤더의 [+ 글 올리기]** — 재설계 뒤에도 유지
- ~~모바일 1열 가로형 카드 · 1024 이상 왼쪽 필터 열~~ — 아래 재설계로 폐기

**SCR-01 재설계** (2026-09-25) — 1차 화면을 본인이 거부했다. 이유는 셋 : **딱딱하고 칙칙함 · 분실/습득 구분이 약함 · 너무 없어 보임.**
본인이 고른 방향은 **의도 우선 + 사진 피드**다. 자세한 정의는 `docs/화면정의서.md` SCR-01.

| | 1차 | 재설계 |
|---|---|---|
| 색 | 회청 잉크 + `#EDF1F4` 캔버스, 색은 유형 배지에만 | 중성 잉크 + 흰 종이, **색은 개념에 붙는다** — 분실 마리골드 `#FFBF2E` · 습득 코발트 `#2F5CE0`(9/26 `#2F5FB1`로 조정)를 면으로 크게 |
| 분실/습득 | 필터 버튼 하나 + 작은 배지 | 첫 화면 맨 위 **의도 선택** 두 칸. `잃어버렸어요` → 습득 글, `주웠어요` → 분실 글(엇갈림) |
| 필터 | 1024 이상 왼쪽 열 | 모든 폭에서 칩 한 줄 + 시트(넓은 화면은 다이얼로그). 유형은 칩 · 시트에서 뺐다 |
| 목록 | 모바일 1열 가로형, 작은 카테고리 아이콘 | 정사각 사진 피드 2 · 3 · 4열. 사진 없는 글은 **포스터**(유형 색 바탕 + 칠한 카테고리 그림) |
| 카드 메타 | 작성자 · 조회수 | 뺐다. 제목 · 장소 · 분실습득일만 |

- 로고 · 파비콘도 새 팔레트로(꼬리표 두 장이 겹친 모양)
- 백엔드 목록 썸네일(`thumbnailUrl`)은 아직 없다. 타입에는 넣지 않았고 `PostCard`의 선택 prop만 있다. 사진 섞인 화면은 목 서버 + 임시 변경으로만 확인했다
- 쓰지 않게 된 `PostFilterPanel` · `ActiveFilterList` · `CategoryIcon` · `useMediaQuery`는 지웠다

**검수 반영 · 시각 체계 정리 · 설정 화면 앞당김** (2026-09-26) — `front-review` 검수에서 나온 SCR-01 구조 흠(본인 승인)을 고치고,
본인의 두 원칙("언제나 사용자 먼저", "AI스러운 느낌은 아예 배제")에 맞춰 시각 체계를 다시 잡았다. 그 김에 단계 5의 SCR-08을 앞당겼다 —
다크 모드를 사용자가 고르게 하려면 고르는 화면이 있어야 해서다.

| | 내용 |
|---|---|
| SCR-01 구조 | 포커스가 body 로 빠지던 다섯 곳(빈 상태 버튼 · 첫 페이지로 · 다시 시도 · 검색 보내기 · 검색어 [×])을 결과 제목으로 · 조건이 걸리면 의도 칸의 건수를 뺌 · [전체 해제]를 칩 줄 맨 앞으로(0건일 때는 [필터 초기화] 하나만) · 64rem 이상 칩 줄 바꿈 · 칩 값 말줄임 · 쪽당 24건 · 스켈레톤 12 · 카드 읽는 순서(제목 → 배지) · 사진 `alt=""` · 첫 줄 사진 즉시 로딩 · 완료 카드 반투명 제거 · 오류 제목을 제목 태그로 |
| 헤더 | 좁은 화면 [+] 아이콘만(이름표) · 휴대폰에서는 선만 두른 버튼 · 설정(톱니) 추가 · 320px 한 줄 |
| 시각 체계 | 아이콘 Phosphor(`bold` 한 굵기) · 반경 4단계 · 간격 2 · 6px 토큰 · 자간 2단계 · 그림 색 토큰 · 눌림 한 가지(투명도) · 탭 하이라이트 통일 · 히어로 구석 꼬리표 장식 제거 |
| 색 | 코발트 `#2F5CE0` → `#2F5FB1`(Tailwind 파랑과 ΔE 3.6 → 31.8) · 마리골드 넓은 면만 `#F5BE3D`. **전후 비교 스크린샷**을 남겼다 — 본인이 원래 색을 고르면 되돌린다 |
| 다크 모드 | 의미 토큰 위에 어둡게 팔레트(전부 계산) · 기기 설정을 따르다가 사용자가 고른다 · `public/theme-init.js`로 첫 화면 전에 적용(CSP) · 탭 사이 동기화 |
| SCR-08 | `/me/settings` "내 정보" → **`/settings` "설정"**(누구나). 프로필(로그인) → 화면 모드 두 칸(미리보기) → 비밀번호 변경(로그인) |
| 포스터 대안 | 지금 그림은 유지. 대안(Phosphor 큰 글리프)은 커밋하지 않고 나란히 비교 스크린샷만 남겼다 |

- 로그인 화면은 아직 자리표시다. 비밀번호를 바꾼 뒤 넘기는 안내(`LoginNoticeState`)는 **단계 2에서** 폼 위에 띄운다

**다음** : 본인이 스크린샷 확인(색 전후 · 포스터 대안 · 설정 화면) → 백엔드 작업 → 단계 2

## 단계 2 — 로그인 · 회원가입(SCR-05, SCR-06) + 온보딩 1층

## 단계 3 — 상세(SCR-03)

상태 변경, 삭제(결과 고지 다이얼로그), 댓글 읽기. 댓글 쓰기·더 보기는 백엔드 `[5.1]` 머지 후.

## 단계 4 — 등록 · 수정(SCR-02, SCR-04)

이미지 업로드 전 축소(긴 변 2048px, JPEG 0.85), 5장 제한, 수정 시 이미지 교체 규칙 고지.
목록의 "분실 글 올리기" · "습득 글 올리기"가 보내는 `?type=LOST|FOUND`로 유형을 미리 고른다.

## 단계 5 — 마이페이지(SCR-07) · 404(SCR-09)

마이페이지는 백엔드 `[6.1]`(`GET /api/members/me/posts`) 이후.
설정(SCR-08)은 2026-09-26에 앞당겨 만들었다(단계 1 기록).

## 단계 2에서 이어받을 것

- 로그인 화면이 `location.state.notice`(`LoginNoticeState`, `app/paths.ts`)를 폼 위에 띄운다 — 설정 화면의 비밀번호 변경 뒤 `"비밀번호를 바꿨습니다. 다시 로그인하세요."`
- 로그인 · 회원가입 폼은 `shared/ui/TextField`(이름 위 · 오류 아래 · 글자 수 · 오른쪽 버튼)를 쓴다. 비밀번호 보기 버튼은 설정 화면의 것과 같은 모양으로
