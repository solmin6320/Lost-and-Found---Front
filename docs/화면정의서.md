# 분실물 찾기 — 화면정의서

작성 기준일 2026-09-22 · SCR-01 재설계 2026-09-25 · 프론트엔드 리포지토리

이 문서는 **기능명세서 3~6장과 백엔드 현재 코드**를 근거로 화면을 정의한다.
명세서에 없는 화면은 만들지 않았고, 백엔드 엔드포인트가 없는 기능은 `백엔드 미구현`으로 표시했다.
UI 구현 전 합의 문서이며, 실제 구현은 이 문서를 따른다.

관련 문서

- `분실물찾기_기능명세서.md` — 엔드포인트와 응답 형태
- `분실물찾기_DB명세서.md` — 컬럼 제약
- `src/app/routes.tsx` — 이 문서의 경로와 1:1로 대응한다
- `src/shared/styles/tokens.css` — 색(분실 · 습득 면 단계)·간격·반경 토큰

## 0. 제품 전제

사용자는 **물건을 잃어버린 직후** 또는 **길에서 뭔가를 주운 직후**에 이 서비스를 연다.
차분히 둘러보는 서비스가 아니다. 모든 화면 결정은 이 전제에서 나온다.

- 모바일 우선(375px 기준). 데스크톱은 넓어진 모바일로 취급한다
- 목록에서 "내 물건인가"를 **1초 안에** 판단할 수 있어야 한다
- 글을 쓰는 사람은 한 손으로, 불안한 상태로 입력한다. 필수 입력을 늘리지 않는다

## 1. 전 화면 공통 규칙

### 1.1 표기 규약

서버는 Enum 문자열을 준다. 화면에는 항상 한글을 쓴다.

| 필드 | 값 → 표기 |
|---|---|
| `type` | `LOST` → **분실** · `FOUND` → **습득** |
| `status` | `OPEN` → **게시중** · `IN_PROGRESS` → **연락중** · `DONE` → **완료** |
| `category` | `WALLET` 지갑 · `ELECTRONICS` 전자기기 · `CARD` 카드 · `CLOTHES` 의류 · `ETC` 기타 |

날짜는 `lostFoundDate`(분실·습득일)와 `createdAt`(등록일)을 **반드시 구분해 라벨을 붙인다.**
둘 다 "날짜"로 쓰면 사용자가 어느 쪽 기준인지 알 수 없다. 목록 필터의 기간은 `lostFoundDate` 기준이다.

### 1.2 색과 배지

**색은 개념에 붙는다**(2026-09-25 재설계). 이 서비스에는 두 갈래뿐이다 — 잃어버림과 주움.

| 개념 | 색 | 쓰는 곳 |
|---|---|---|
| 잃어버림 | **마리골드** — 면 `#FFBF2E` + 글자 `#3D2600`(8.6:1) · 흰 바탕 위 글자 `#8A5A00`(5.9:1) | LOST 글의 배지 · 포스터, `물건을 잃어버렸어요`, 분실 글 올리기 |
| 주움 | **코발트** — 면 `#2F5CE0` + 흰 글자(5.6:1) · 흰 바탕 위 글자 `#1F3FA8`(9.0:1) | FOUND 글의 배지 · 포스터, `물건을 주웠어요`, 습득 글 올리기 |

- ⛔ **"색을 쓰는 곳은 유형 배지뿐" 규칙은 폐기했다.** 회청 잉크와 회색 캔버스뿐인 화면이 칙칙하고 초라해 보인 원인이었다.
  두 색은 배지뿐 아니라 **면**(의도 선택, 사진 없는 글의 포스터, 등록 권유)으로 크게 쓴다
- 색은 보여주는 글이 아니라 **사용자가 한 일**을 따른다. `잃어버렸어요`는 습득 글을 보여주지만 분실 색이다
- 두 색은 노랑 ↔ 파랑이라 적록색각이상에서도 갈라지고, 명도가 0.59 대 0.14라 흑백에서도 밝은 면 / 어두운 면으로 갈린다
- 나머지(글자 · 선 · 공통 버튼)는 중성 잉크와 흰 종이로 조용히 둔다. 값과 대비는 `src/shared/styles/tokens.css` 머리 주석에 있다

배지는 두 축을 **색으로 섞지 않는다.** 유형과 상태는 다른 정보다.

| 축 | 표현 |
|---|---|
| 유형 (분실/습득) | **채운 배지.** 위 두 색의 면 + 글자 |
| 상태 (게시중/연락중/완료) | **외곽선 배지 + 점.** 색을 쓰지 않는다. 라벨 텍스트 · 점 모양 · 선 굵기로 가른다 |

- 색만으로 구분하지 않는다. **배지에는 항상 한글 라벨이 함께 있다**
- 사진 위에 겹칠 때(`surface="photo"`)는 배지가 불투명한 바탕을 가진다 — 유형 배지는 흰 테, 연락중은 흰 알약, 완료는 잉크 도장(✓ 완료)
- **완료는 눈에 덜 띈다.** 목록 카드는 사진을 흑백으로 낮추고 글자를 한 단계 흐린다. 카드 전체를 반투명으로 만들지 않는다 — 제목이 4.5:1 아래로 떨어진다
- 빨강은 삭제(파괴적 동작)에만 쓴다. 배지 · 면에 빨강을 쓰지 않는 이유가 이것이다

### 1.3 네 가지 상태 — 모든 화면이 전부 가진다

하나라도 빠지면 화면이 거짓말을 한다.

| 상태 | 공통 규칙 |
|---|---|
| 로딩 | 스피너가 아니라 **스켈레톤.** 실제 콘텐츠와 같은 높이·같은 자리를 차지해 레이아웃이 튀지 않는다 |
| 비어 있음 | 빈 화면은 오류처럼 보인다. **왜 비었는지 + 다음에 할 일**을 화면이 말한다 |
| 오류 | 백엔드 `ErrorResponse.message`를 **그대로** 보여준다. 프론트가 문구를 새로 짓지 않는다 |
| 권한 | 권한 없는 사용자에게 수정·삭제·상태 변경 버튼을 **보이지 않게** 한다. 비활성화가 아니라 숨김 |

> **오류 문구를 프론트가 짓지 않는 이유.** 백엔드 `ErrorCode`가 이미 한글 문장을 가지고 있다
> (`"존재하지 않는 게시글입니다"`, `"이미 사용 중인 닉네임입니다"`). 프론트가 따로 지으면
> 같은 상황에 두 개의 문장이 생기고, 백엔드가 문구를 고쳐도 화면은 안 바뀐다.
>
> 프론트가 직접 쓰는 문구는 셋뿐이다 — **빈 상태 / 확인 다이얼로그 / 결과 고지(인라인)**.
> 그리고 **응답 자체가 없을 때**(네트워크 끊김, 타임아웃) 한 문장 :
> `"연결에 실패했습니다. 네트워크를 확인하고 다시 시도하세요."`

### 1.4 오류 응답 → 화면 동작

응답 형식은 `{ "code": "POST_NOT_FOUND", "message": "존재하지 않는 게시글입니다" }` 하나로 고정이다.
**`code`로 분기하고 `message`를 보여준다.** 상태 코드만 보고 분기하면 401이 네 종류라 구분이 안 된다.

| HTTP | code | 화면 동작 |
|---|---|---|
| 401 | `INVALID_ACCESS_TOKEN` | 화면에 아무것도 띄우지 않고 `POST /api/auth/reissue`를 **1회** 시도한다. 성공하면 원래 요청을 재시도, 실패하면 1.5의 세션 만료 처리 |
| 401 | `INVALID_CREDENTIALS` | 로그인 폼 하단에 `message` 인라인 표시. 입력값은 지우지 않는다 |
| 401 | `REFRESH_TOKEN_MISMATCH` `INVALID_REFRESH_TOKEN` | 세션 만료 처리(1.5) |
| 403 | `FORBIDDEN_ACCESS` | 남의 글을 건드린 것이다. 상세 화면으로 되돌리고 `message`를 띄운다 |
| 404 | `POST_NOT_FOUND` `MEMBER_NOT_FOUND` | 화면 본문 전체를 빈 상태로 바꾸고 `message` + `[목록으로]` |
| 409 | `DUPLICATE_EMAIL` `DUPLICATE_NICKNAME` | **해당 입력 필드 아래**에 `message`. 상단 배너로 몰지 않는다 |
| 409 | `INVALID_STATUS_TRANSITION` | 상태 컨트롤 옆에 `message`. 상세를 다시 불러 현재 상태를 맞춘다 |
| 423 | `ACCOUNT_LOCKED` | 로그인 폼을 잠금 화면으로 전환(SCR-05 참고) |
| 400 | `INVALID_INPUT` | 필드별 인라인. 어느 필드인지 알 수 없으면 제출 버튼 위에 한 줄 |
| 400 | `PASSWORD_MISMATCH` | "현재 비밀번호" 필드 아래 인라인 |
| 400 | `INVALID_IMAGE_EXTENSION` `EXCEEDED_IMAGE_COUNT` | 업로드 영역 아래 인라인. **단, 둘 다 UI가 먼저 막으므로 여기까지 오면 안 된다** |
| 405 · 500 | `METHOD_NOT_ALLOWED` `INTERNAL_SERVER_ERROR` | `message` + `[다시 시도]` |

### 1.5 인증과 권한

| | |
|---|---|
| 액세스 토큰 | JS 메모리에만 둔다. localStorage에 쓰지 않는다. 새로고침하면 사라진다 |
| 리프레시 토큰 | httpOnly 쿠키. 프론트 코드가 읽지도 쓰지도 않는다 |
| 새로고침 복구 | 앱이 뜰 때 `POST /api/auth/reissue`를 1회 호출한다. 성공하면 로그인 상태를 되살리고, 실패(401)하면 조용히 비로그인으로 둔다. **이때는 로그인 화면으로 보내지 않는다** |
| 세션 만료 처리 | 메모리 토큰을 비우고 `/login?redirect={현재경로}` 로 이동. 로그인 화면 상단에 `"로그인이 만료됐습니다. 다시 로그인하세요."` |

**작성자 본인 판정은 `memberId`로 한다. 닉네임으로 하지 않는다.**
닉네임은 바뀔 수 있어서(`[3.6]`) 비교가 깨진다.

- 로그인 응답(`LoginResponse`)에는 회원 식별자가 없다(`accessToken` `tokenType` `accessTokenExpires`뿐).
  로그인 성공 직후 **`GET /api/members/me`를 한 번 호출해** `id`·`nickname`을 메모리에 담는다
- `PostDetailResponse.memberId`, `CommentResponse.memberId`와 비교한다
- `PostListResponse`에는 `memberId`가 **없다**(닉네임만). 그래서 목록 카드에는 소유자 전용 동작을 두지 않는다.
  마이페이지(SCR-07)는 응답 전체가 내 글이므로 판정이 필요 없다

로그인이 필요한 화면에 비로그인으로 들어오면 `/login?redirect={원래경로}` 로 보낸다.
로그인에 성공하면 `redirect`로 되돌린다. 목록으로 떨어뜨리지 않는다.

### 1.6 결과 고지 — 누르기 전에, 한 번, 구체적으로

사용자가 누르기 **전에** 그 선택이 무엇을 바꾸는지 알아야 한다.
같은 내용을 두 번 묻지 않는다. 경고가 반복되면 사용자는 읽지 않고 누르는 법을 배운다.

| 되돌릴 수 | 형식 |
|---|---|
| 있음 | **인라인 한 줄.** 버튼·입력 바로 아래, 작고 흐리게. 진행을 막지 않는다 |
| 없음 | **확인 다이얼로그.** 결과를 문장으로 쓴다. "삭제"는 파괴적 색상, **기본 포커스는 "취소"** |

고지 대상은 여섯 가지다. 화면별 상세에 실제 문구를 적었다.

| 동작 | 알릴 것 | 형식 | 화면 |
|---|---|---|---|
| 게시글 등록 | 사진은 최대 5장 | 인라인 | SCR-02 |
| 게시글 수정 | 새 사진을 올리면 기존 사진이 **전부 교체**된다 | 인라인 | SCR-04 |
| 게시글 삭제 | 사진과 **댓글까지** 사라진다. 되돌릴 수 없다 | 다이얼로그 | SCR-03 |
| 상태 → 완료 | **되돌릴 수 없다** | 다이얼로그 | SCR-03 · SCR-07 |
| 비밀번호 변경 | **이 기기 포함 모든 기기에서 로그아웃**된다 | 인라인 | SCR-08 |
| 닉네임 변경 | 기존 글·댓글의 이름이 **전부 바뀐다** | 인라인 | SCR-08 |

### 1.7 폼 공통

- 검증은 제출 시점이 아니라 **필드를 벗어날 때**. 제출 후 다섯 개가 한꺼번에 빨개지면 늦다
- 서버 검증 메시지는 **해당 필드 아래**에 붙인다. 상단 배너로 몰지 않는다
- **전송 중에는 제출·취소 버튼을 잠근다.** 사진 5장이면 몇 초 걸리고, 그 사이 중복 클릭이 들어가면 글이 두 개 만들어진다
- 취소를 눌러도 이미 서버에 닿은 요청은 처리된다. 버튼 문구를 "취소"가 아니라 상황에 맞게 잠근 상태로 둔다
- 작성 중 이탈은 `beforeunload` + 라우터 이탈 확인 :
  `"작성 중인 내용이 있습니다. 나가면 저장되지 않습니다."`

### 1.8 이미지 공통

- 게시글당 **최대 5장.** 6장째를 고른 순간 UI가 막는다. 서버까지 보내고 400을 받지 않는다
- 확장자는 jpg / jpeg / png / gif만 고를 수 있게 `accept`로 제한한다
- 사진 없는 글이 많다. **자리표시는 포스터**로 만든다 — 유형 색의 연한 바탕 + 칠한 카테고리 그림(지갑 · 전자기기 · 카드 · 의류 · 기타) + 카테고리 이름. 회색 네모나 작은 아이콘 하나를 두지 않는다
- 목록 썸네일은 **1:1 고정 비율로 자른다.** 세로 사진 때문에 카드 높이가 들쭉날쭉하면 스캔이 안 된다
- `alt`는 "이미지"가 아니라 **게시글 제목**을 쓴다

### 1.9 접근성 최소선

- 모든 폼 입력에 `label`. placeholder로 대신하지 않는다
- 배지·상태를 색만으로 구분하지 않는다(1.2)
- 375px에서 가로 스크롤이 생기지 않는다
- 터치 대상 최소 44×44
- 포커스 링을 지우지 않는다
- 다이얼로그는 포커스를 가두고, Esc로 닫히며, 닫으면 열었던 버튼으로 포커스가 돌아온다

### 1.10 공통 레이아웃

모든 화면이 공유한다.

```
┌─────────────────────────────────────┐
│ 헤더 (sticky, 56px)                  │
│  [꼬리표] 분실물 찾기  [+ 글 올리기] [로그인] │
├─────────────────────────────────────┤
│                                     │
│  본문 (좌우 여백 16px, 640 이상 24px)   │
│                                     │
├─────────────────────────────────────┤
│ 푸터                                 │
└─────────────────────────────────────┘
```

- 본문 폭은 둘이다. **목록**은 페이지 폭(`--layout-page` 1216px)을 다 쓴다 — 1440에서 양옆이 비지 않게 피드 열을 늘린다.
  **읽는 화면**(상세 · 폼)은 700px(`--layout-max`)로 좁힌다
- 헤더는 셋만 둔다 — 로고(목록으로) · `[+ 글 올리기]` · 로그인/계정. 로고는 마리골드 · 코발트 꼬리표 두 장이 겹친 모양이다
- 헤더 우측은 로그인 상태에 따라 갈린다. 비로그인 `[로그인]` / 로그인 `닉네임 ▾`(내가 쓴 글 · 내 정보 · 로그아웃)
- 로그아웃 → `POST /api/auth/logout` `[3.4]`. 되돌릴 수 있는 동작이므로 **확인 다이얼로그를 띄우지 않는다**
- 첫 요소는 화면에 보이지 않는 `본문으로 건너뛰기` 링크다. Tab을 누르면 나타난다

## 3. 화면별 상세

### SCR-01 · 게시글 목록 · `/`

| 항목 | 내용 |
|---|---|
| **대응** | `[4.2]` 게시글 목록 조회 → `GET /api/posts?keyword=&type=&category=&location=&from=&to=&status=&page=&size=` |
| **권한** | 비로그인 가능. 소유자 전용 요소 없음 |
| **방향** | **의도 우선 + 사진 피드**(2026-09-25 재설계). 1차(왼쪽 필터 열 + 회색 가로형 목록)는 "딱딱하고 칙칙함 · 분실/습득 구분이 약함 · 초라함"으로 거부됐다 |

**진입 · 이탈**

| 어디서 들어오나 | 어디로 나가나 |
|---|---|
| 첫 진입 · 헤더 로고 · 글 삭제 후 · `[목록으로]` | 카드 클릭 → `SCR-03` |
| | 헤더 `[+ 글 올리기]` → `SCR-02` (비로그인이면 `/login?redirect=/posts/new`) |
| | 의도 모드의 `[분실 글 올리기]` / `[습득 글 올리기]` → `SCR-02` `?type=LOST` / `?type=FOUND` (비로그인이면 로그인을 거친다) |

**구성 요소** — 모든 폭에서 같은 순서다. 넓어지면 칸이 늘 뿐, 필터가 옆 열로 빠지지 않는다.

**① 의도 선택 — 맨 위, 두 색 면**

분실/습득은 필터 하나가 아니라 이 서비스의 구조다. 첫 화면 맨 위에 헤드라인 `잃어버렸나요, 주웠나요?`와 큰 선택지 둘을 둔다.
헤드라인을 질문으로 둔 것은 두 선택지가 그 답이 되게 하기 위해서다.

⚠️ **사용자가 고르는 것과 보여줄 글이 엇갈린다.** 잃어버린 사람이 알고 싶은 건 "누가 주웠나"다.

| 선택지 | 색(사용자가 한 일) | 거는 조건 | 선택지 아래 한 줄 | 결과 제목 |
|---|---|---|---|---|
| (고르지 않음) | — | 없음 | — | `최근 올라온 물건` |
| `물건을 잃어버렸어요` | 마리골드 | `?type=FOUND` | `주워진 물건 12건 보기` | `누군가 주워 둔 물건` |
| `물건을 주웠어요` | 코발트 | `?type=LOST` | `주인이 찾는 물건 13건 보기` | `주인이 찾고 있는 물건` |

- 두 선택지는 **링크**다(새 탭 열기 · 주소 공유). 검색어 · 필터는 그대로 두고 1쪽으로 간다
- 고른 쪽은 `aria-current`, 한 줄이 `… 보는 중`으로 바뀌고, 다른 쪽은 연한 면으로 물러난다(누르면 바로 갈아탄다)
- **전체로 되돌아가는 길**은 고른 선택지 귀퉁이의 `[×]`(`선택 풀고 모든 글 보기`)다. 누르면 방금 풀린 선택지로 포커스가 돌아온다
- 건수는 `GET /api/posts?type=FOUND&size=1`의 `page.totalElements`. 목록과 따로 불러와 **목록을 막지 않는다.** 불러오는 동안 숫자 자리를 비워 두고(글자가 밀리지 않는다), 실패하면 숫자 대신 `모두 보기`
- 건수는 유형 전체다(검색어 · 필터 무관). 선택지를 누른 직후의 목록 수와 같아야 믿는다
- 좁은 화면에서도 **나란히 두 칸**이다. 위아래로 쌓으면 피드가 첫 화면 밖으로 밀린다. 문구는 `물건을 / 잃어버렸어요`, `주워진 물건 / 12건 보기`처럼 두 선택지가 같은 자리에서 끊겨 줄이 맞는다. 375px 첫 화면에 첫 줄 카드의 사진 윗부분이 보인다
- 귀퉁이의 큰 꼬리표는 로고와 같은 모양의 장식이다(`aria-hidden`)

**② 검색 · 필터 — 검색은 크게, 필터는 접는다**

- 검색창은 의도 선택 바로 아래, 옅은 면으로 채운 52px 칸. Enter(휴대폰의 [검색])에서 보낸다
- **왼쪽 필터 열은 없앴다.** 모든 폭에서 칩 한 줄(`카테고리 · 상태 · 장소 · 기간`)이고, 누르면 시트가 열린다. 좁은 화면은 바텀 시트, 768 이상은 가운데 다이얼로그 모양이다(같은 컴포넌트, CSS만 다르다). 1024 이상에서는 검색창과 칩이 한 줄에 선다
- 걸린 칩은 잉크로 채우고 값과 `[×]`를 붙인다(`카테고리: 지갑 ×`). 걸린 칩을 앞으로 모은다. `[전체 해제]`는 결과 제목 줄 끝
- **유형(분실/습득)은 칩 · 시트에서 뺐다.** 판단 근거
  - 같은 주소 값(`type`)을 고치는 곳이 둘이면, 한쪽을 바꾼 뒤 다른 쪽이 무엇을 말하는지 헷갈린다. 의도 선택은 늘 화면 맨 위에 보인다
  - 칩 줄이 하나 짧아져 320px에서 걸린 조건이 덜 숨는다
  - 그래서 `[전체 해제]` · `필터 초기화`도 **유형은 남긴다.** 검색어처럼 화면 위에 그대로 보이는 값이다. 유형은 `[×]`로만 푼다
- 장소 · 기간처럼 글자를 치는 조건은 시트의 `[적용하기]`에서 한 번에 반영한다

**③ 사진 피드 — 카드 위계**

| 순위 | 요소 |
|---|---|
| 1 | 정사각 사진(없으면 포스터) + 제목(2줄에서 자름, 16px 굵게 · 넓은 칸 18px) |
| 2 | 사진 위 왼쪽 위 배지 — 유형(분실/습득), 그리고 연락중 · 완료 |
| 3 | 장소(핀 그림 + 스크린리더용 `장소`, 한 줄 말줄임) · 분실습득일(`분실일` / `습득일` 라벨) |

- 열 수는 **결과 칸의 폭**으로 정한다(컨테이너 쿼리) — 2열(320 · 375 포함) → 3열(34rem, 태블릿) → 4열(54rem, 데스크톱)
- 테두리 · 그림자가 없다. 사진의 사각형이 카드의 모양이다. 카드 전체가 제목 링크 하나(`::after`)이고, 포커스 링은 카드 전체를 두른다
- 문서 순서는 제목이 먼저, 사진은 CSS `order`로 위에 올린다 — 스크린리더가 제목부터 읽는다
- **작성자 · 조회수는 뺐다.** "내 물건인가"를 가리는 데 쓰이지 않고, 좁은 두 칸에서 줄만 늘린다. 상세에서 본다
- **게시중은 표시하지 않는다**(기본값). 연락중은 흰 알약 `◐ 연락중`, 완료는 잉크 도장 `✓ 완료`. 색이 아니라 라벨로 읽는다
- **완료** 카드는 사진을 흑백 + 반투명으로, 포스터는 흑백 + 그림만 옅게, 제목 · 장소 · 날짜는 한 단계 흐린 글자(5.6:1)로 낮춘다
- 사진은 1:1로 자른다(`object-fit: cover`). 세로로 긴 사진도 카드 높이를 흔들지 않는다. 밝은 사진이 흰 종이에 녹지 않게 아주 옅은 테를 두른다. `alt`는 게시글 제목, `loading="lazy"`
- **사진 없는 글 = 포스터.** 유형 색의 연한 바탕 + 칠한 카테고리 그림(몸통 · 진한 윤곽 · 밝은 면) + 왼쪽 아래 카테고리 이름. 그림은 글마다 조금씩 다르게 기울인다. 스무 장이 전부 포스터여도 삽화 카탈로그처럼 보여야 한다
- **본문(`content`)은 카드에 싣지 않는다.** 백엔드 `PostListResponse`도 빼놨다. 5000자 × 20건이면 10만 자다
- 목록 썸네일(`thumbnailUrl`)은 백엔드에 아직 없다. 머지되면 `PostListResponse`에 `thumbnailUrl: string | null`을 넣고 `PostCard`의 `thumbnailUrl`로 넘기기만 하면 된다
- 의도 · 검색 · 필터 · 페이지는 **URL 쿼리스트링**에 싣는다(`/?type=FOUND&keyword=지갑&page=2`). 뒤로가기 · 새로고침 · 링크 공유가 그대로 동작하고, 백엔드 파라미터 이름과 같아진다
- 정렬은 등록일 내림차순 고정이다. 정렬 UI를 두지 않는다 — 서버가 `sort`를 무시한다
- 조건을 바꾸는 동안 직전 목록과 결과 수를 흐리게 남긴다(`keepPreviousData`). 결과 수는 `aria-live`로 알린다
- 페이지를 넘기면 결과 제목으로 스크롤하고 포커스를 옮긴다

**④ 다음 행동 — 의도 모드의 결과 끝**

| 의도 | 문구 | 버튼(색) | 주소 |
|---|---|---|---|
| 잃어버렸어요 | `찾는 물건이 없나요?` / `분실 글을 올려 두면 주운 사람이 연락할 수 있어요.` | `[+ 분실 글 올리기]` 마리골드 | `/posts/new?type=LOST` |
| 주웠어요 | `주운 물건과 맞는 글이 없나요?` / `습득 글을 올려 두면 잃어버린 사람이 찾아볼 수 있어요.` | `[+ 습득 글 올리기]` 코발트 | `/posts/new?type=FOUND` |

- 비로그인이면 `paths.loginThenReturn`으로 로그인을 거쳐 돌아온다
- 페이지 이동 아래, 연한 색 면 한 장. 조건 검색이 0건일 때도 보인다. **그 유형의 글이 아예 없을 때는 빈 상태가 같은 버튼을 이미 말하므로 두 번 두지 않는다**

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 카드 스켈레톤 8개(2 · 3 · 4열 어디서든 줄이 찬다). 정사각 + 제목 2줄 + 장소 · 날짜 2줄로 실제 카드와 같은 격자 · 같은 높이. 결과 수 자리와 선택지 건수 자리도 잡아 둔다 |
| 비어 있음 (검색 · 필터 있음) | `"조건에 맞는 글이 없어요."` / `"검색어나 필터를 바꿔 보세요."` + `[필터 초기화]`(필터가 없으면 `[검색어 지우기]`). 의도 모드면 아래에 다음 행동 |
| 비어 있음 (의도만, 그 유형 0건) | 잃어버렸어요 : `"아직 주워 둔 물건이 없어요."` + `[분실 글 올리기]` / 주웠어요 : `"아직 주인이 찾는 물건이 없어요."` + `[습득 글 올리기]`. 그림은 올릴 글 색의 꼬리표 |
| 비어 있음 (조건 없음) | `"아직 올라온 글이 없어요."` / `"잃어버렸거나 주운 물건을 올려 보세요."` + `[글 올리기]` |
| 비어 있음 (끝을 넘은 페이지) | `"9페이지에는 글이 없어요."` / `"조건에 맞는 글 25건은 앞 페이지에 있어요."` + `[첫 페이지로]` |
| 오류 | 서버 `message` + `[다시 시도]`. 응답 자체가 없으면 `"연결에 실패했습니다. 네트워크를 확인하고 다시 시도하세요."` |
| 권한 | 해당 없음. 전체 공개, 소유자 동작 없음 |

빈 상태 · 오류는 사진 자리에 옅은 면 한 장으로 둔다. 흰 종이 위 빈자리는 고장처럼 보인다.

**동작과 결과 고지** — 되돌릴 수 없는 동작이 없다. 다이얼로그를 띄우지 않는다.

**예외**

| 상황 | 화면 |
|---|---|
| 400 `INVALID_INPUT` (`from > to`) | 시트의 기간 아래 인라인. 보내기 전에 화면이 막는다. 주소에 거꾸로 된 기간이 들어오면 버린다 |
| 500 | 목록 자리에 오류 상태 + `[다시 시도]`. 선택지 건수는 숫자만 빠진다 |
| 401 | 목록은 `permitAll`이라 발생하지 않는다. 만료된 토큰으로 요청해도 비로그인으로 조용히 처리된다 |
| 썸네일 주소가 깨짐 | 포스터로 바꾼다(`onError`) |

### SCR-02 · 게시글 등록 · `/posts/new`

| 항목 | 내용 |
|---|---|
| **대응** | `[4.1]` 등록 + `[4.5]` 이미지 → `POST /api/posts` (`multipart/form-data`) |
| **권한** | **로그인 필요.** 비로그인 진입 시 `/login?redirect=/posts/new` |

**진입 · 이탈**

| 어디서 들어오나 | 어디로 나가나 |
|---|---|
| 헤더 `[+ 글 올리기]` · `SCR-01` 빈 상태의 `[글 올리기]` | 성공(201) → `SCR-03` 새 글 상세 |
| `SCR-01` 의도 모드의 `[분실 글 올리기]` · `[습득 글 올리기]` (`?type=LOST` · `?type=FOUND`) | |
| 로그인 후 `redirect` 복귀 | `[취소]` · 뒤로가기 → 직전 화면. 입력이 있으면 이탈 확인 |

**구성 요소**

```
글 올리기
+-----------------------------------+
| 어떤 글인가요? *                    |
|  ( ) 잃어버렸어요   ( ) 주웠어요     |   <- type. 라디오, 기본 미선택
| 제목 *                    0/100    |
| 카테고리 *  [지갑 v]                |
| 장소 *                    0/100    |
| 언제 *      [2026-09-20]           |   <- 오늘 이후 선택 불가
| 자세한 설명 *            0/5000    |
| 사진                               |
|  [+] [img] [img]                   |
|  사진은 최대 5장까지 올릴 수 있습니다. |   <- 인라인 고지
|                                    |
|            [취소]  [올리기]         |
+-----------------------------------+
```

- 필수는 6개다(`type` `title` `category` `location` `lostFoundDate` `content`). **필수를 늘리지 않는다.** 사진은 선택이다
- `type`은 Enum 이름이 아니라 **사용자의 말**로 묻는다 — "잃어버렸어요 / 주웠어요"
- `type` 쿼리로 유형을 미리 선택한다(단계 4 구현)
- 날짜는 `@PastOrPresent`다. **달력에서 미래 날짜를 아예 못 고르게 막는다.** 서버까지 보내고 400을 받지 않는다
- 글자 수 카운터를 제목·장소·본문에 둔다(100 / 100 / 5000). DB 제약과 같은 값이다

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 폼은 즉시 뜬다. **제출 중**에는 제출·취소 버튼을 잠그고 버튼 문구를 `"올리는 중…"`으로 바꾼다 |
| 비어 있음 | 해당 없음(입력 화면) |
| 오류 | 필드별 인라인. 어느 필드인지 모르면 제출 버튼 위 한 줄 |
| 권한 | 비로그인은 이 화면에 도달하지 못한다 |

**동작과 결과 고지**

| 대상 | 형식 | 문구 |
|---|---|---|
| 사진 개수 | **인라인** | `"사진은 최대 5장까지 올릴 수 있습니다."` — 업로드 영역 아래 상시 |
| 6장째 선택 | **인라인** | `"사진은 5장까지입니다. 3장을 더 고를 수 없습니다."` — 고른 순간 UI가 막는다. 서버로 보내지 않는다 |
| 작성 중 이탈 | **다이얼로그** | `"작성 중인 내용이 있습니다. 나가면 저장되지 않습니다."` · 기본 포커스 `[계속 작성]` |

등록은 되돌릴 수 있다(바로 지울 수 있다). **제출에 확인 다이얼로그를 띄우지 않는다.**

**예외**

| 상황 | 화면 |
|---|---|
| 401 `INVALID_ACCESS_TOKEN` | 인터셉터가 재발급 후 재전송. 재발급 실패 시 **입력값을 보존한 채** 로그인으로 보내고 복귀 후 되살린다 |
| 400 `INVALID_INPUT` | 필드별 인라인 |
| 400 `INVALID_IMAGE_EXTENSION` `EXCEEDED_IMAGE_COUNT` | 업로드 영역 아래. UI가 먼저 막으므로 도달하면 안 되는 경로다 |
| 500 | 제출 버튼 잠금을 풀고 `message` 표시. **입력값을 지우지 않는다** |

### SCR-03 · 게시글 상세 · `/posts/:postId`

| 항목 | 내용 |
|---|---|
| **대응** | `[4.3]` 상세 → `GET /api/posts/{id}` · `[4.6]` 상태 변경 → `PATCH /api/posts/{id}/status` · `[4.4]` 삭제 → `DELETE /api/posts/{id}` · `[5.1]` 댓글 |
| **권한** | 조회는 비로그인 가능. **수정·삭제·상태 변경은 작성자 본인만** |

**진입 · 이탈**

| 어디서 들어오나 | 어디로 나가나 |
|---|---|
| `SCR-01` 카드 · `SCR-07` 카드 · 등록/수정 성공 후 · 외부 공유 링크 | `[수정]` → `SCR-04` |
| | 삭제 완료 → `SCR-01` |
| | 작성자 닉네임은 링크가 아니다(회원 공개 프로필이 없다) |

**구성 요소** — 위에서 아래로 읽는 순서를 고정한다.

```
검은색 반지갑 잃어버렸어요           <- 제목
[분실] (o)게시중                    <- 배지
+-------------------------+
|       사진 (스와이프)      |        <- 없으면 목록과 같은 포스터(1.8)
+-------------------------+
강남역 2번 출구 · 2026-09-20        <- 장소 · 분실습득일
지갑                                <- 카테고리

본문 …                              <- content

김솔민 · 2026-09-21 등록 · 조회 12   <- 메타
--------------------------------
【작성자 본인일 때만】
 상태  [게시중] [연락중] [완료]
 [수정]                     [삭제]
--------------------------------
댓글 5
 …
```

- 사진은 스와이프 캐러셀. `alt`에 **게시글 제목**을 넣는다. "이미지"라고 쓰지 않는다
- 사진이 없으면 목록과 같은 포스터(유형 색 바탕 + 카테고리 그림, 1.8). 회색 네모를 두지 않는다
- 조회수는 비로그인 조회에서 오르지 않는다. 화면은 응답값을 그대로 보여준다
- 수정·삭제·상태 컨트롤은 `detail.memberId === me.id`일 때만 **렌더한다.** 비활성 버튼을 남기지 않는다

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 제목 1줄 · 배지 2개 · 사진 영역(1:1) · 본문 4줄 스켈레톤 |
| 비어 있음 | 댓글 0건 → `"아직 댓글이 없습니다."` / `"이 물건을 본 적 있다면 알려주세요."` |
| 오류 | 404면 본문 전체를 `"존재하지 않는 게시글입니다"`(서버 message) + `[목록으로]`. 그 외는 `message` + `[다시 시도]` |
| 권한 | 비로그인·타인에게 수정·삭제·상태 컨트롤을 **보여주지 않는다.** 댓글 입력창은 비로그인에게 `[로그인하고 댓글 쓰기]`로 바꾼다 |

**동작과 결과 고지**

**① 게시글 삭제 — 확인 다이얼로그.** 되돌릴 수 없다.

```
+--------------------------------------+
| 이 글을 삭제할까요?                    |
|                                      |
| 사진 3장과 댓글 5개가 함께 사라집니다.   |
| 되돌릴 수 없습니다.                    |
|                                      |
|              [취소]  [삭제]           |
+--------------------------------------+
```

- 숫자는 실제 값(`images.length`, `totalCommentCount`)을 넣는다. `"정말 삭제하시겠습니까?"`는 아무 정보도 주지 않는다
- 0인 항목은 문장에서 뺀다. 사진만 있으면 `"사진 3장이 함께 사라집니다. 되돌릴 수 없습니다."`, 둘 다 없으면 `"되돌릴 수 없습니다."`
- `[삭제]`는 파괴적 색상, **기본 포커스는 `[취소]`**
- 삭제가 댓글까지 지우는 건 `PostService.delete()`가 `commentRepository.deleteByPostId()`를 먼저 호출하기 때문이다. 사진은 S3 객체까지 지운다. **둘 다 사용자가 예상하지 못하는 결과라 반드시 알린다**
- 완료(`DONE`) 글도 삭제할 수 있다. 상태로 막지 않는다
- 성공(204) → `SCR-01`로 이동 + `"글을 삭제했습니다."`

**② 상태 변경 — 완료만 다이얼로그.**

| 전이 | 형식 |
|---|---|
| 게시중 ↔ 연락중 | **확인 없이 바로 반영.** 서로 되돌릴 수 있다. 되돌릴 수 있는 일에 다이얼로그를 띄우지 않는다 |
| → 완료 | **확인 다이얼로그** |

```
+--------------------------------------+
| 완료로 바꿀까요?                       |
|                                      |
| 완료로 바꾸면 다시 게시중이나 연락중으로 |
| 되돌릴 수 없습니다.                    |
|                                      |
|           [취소]  [완료로 바꾸기]      |
+--------------------------------------+
```

- 이미 완료인 글에서는 상태 컨트롤을 **읽기 전용 배지로 바꾼다.** 누를 수 없는 버튼을 남기지 않는다
- 같은 상태를 다시 누르는 것은 서버가 200으로 받아준다(멱등). 화면도 오류로 다루지 않는다

**③ 댓글 — 쓰기는 백엔드 구현 중**(`feature/comment-crud`, 기능명세서 `[5.1]` 2026-09-23 확정). 화면은 정의해 두고 머지되면 붙인다.

| 기능 | 엔드포인트 | 상태 |
|---|---|---|
| 목록(처음 20건) | `GET /api/posts/{id}` 응답의 `comments` | **구현 완료** — 읽기는 지금도 된다 |
| 더 보기 | `GET /api/posts/{id}/comments?page=` | 구현 중 |
| 등록 | `POST /api/posts/{id}/comments` | 구현 중 |
| 수정 | `PUT /api/comments/{id}` | 구현 중 |
| 삭제 | `DELETE /api/comments/{id}` | 구현 중 |

- 상세 응답이 **오래된 순 20건**을 준다. `totalCommentCount > 20`이면 `[댓글 더 보기]`를 띄운다
- `[댓글 더 보기]`는 **`page=1`부터** 부른다. `page=0`은 상세 응답의 20건과 같다
- **`size`를 보내지 않는다.** 서버가 20으로 고정하고 보내도 무시한다. 그래야 `page=1`이 21번째부터 정확히 이어진다
- `updatedAt`이 `null`이 아니면 작성 시각 옆에 `(수정됨)`을 붙인다
- 댓글 수정·삭제는 `comment.memberId === me.id`일 때만 보인다
- 댓글 삭제는 되돌릴 수 없지만 잃는 것이 300자 한 줄뿐이다. **다이얼로그 대신 인라인 확인**(`[삭제]` → `[정말 삭제] [취소]`)으로 마찰을 낮춘다. 다이얼로그를 남발하면 게시글 삭제 다이얼로그를 읽지 않게 된다
- 댓글 입력은 300자 제한(DB `VARCHAR(300)`). 카운터를 둔다
- 댓글 본문은 **반드시 이스케이프해서 렌더한다.** `dangerouslySetInnerHTML`을 쓰지 않는다

**예외**

| 상황 | 화면 |
|---|---|
| 404 `POST_NOT_FOUND` | 본문 전체를 빈 상태로. `message` + `[목록으로]` |
| 403 `FORBIDDEN_ACCESS` | 남의 글에 수정·삭제·상태 변경이 들어간 경우다. `message`를 띄우고 상세를 다시 불러 화면을 맞춘다 |
| 409 `INVALID_STATUS_TRANSITION` | 상태 컨트롤 옆에 `"완료된 게시글은 상태를 되돌릴 수 없습니다"`. 상세를 다시 불러 실제 상태로 맞춘다 |
| 401 | 인터셉터 재발급 → 실패 시 세션 만료 처리. 다이얼로그가 열려 있었다면 닫는다 |
| `postId`가 숫자가 아님 | 라우터는 통과한다(`:postId`는 문자열을 받는다). 서버가 400을 주면 404 화면과 같게 처리한다 |

### SCR-04 · 게시글 수정 · `/posts/:postId/edit`

| 항목 | 내용 |
|---|---|
| **대응** | `[4.4]` 수정 + `[4.5]` 이미지 → `PUT /api/posts/{id}` (`multipart/form-data`) |
| **권한** | **작성자 본인만.** 진입 시 `GET /api/posts/{id}`로 `memberId`를 확인하고, 본인이 아니면 상세로 되돌린다 |

**진입 · 이탈**

| 어디서 들어오나 | 어디로 나가나 |
|---|---|
| `SCR-03`의 `[수정]` (작성자에게만 보인다) | 성공(200) → `SCR-03` |
| URL 직접 입력 | `[취소]` → `SCR-03`. 변경이 있으면 이탈 확인 |
| | 본인 아님 → `SCR-03` + `"본인이 작성한 게시글, 댓글만 처리할 수 있습니다"` |

**구성 요소** — SCR-02와 같은 폼에 현재 값이 채워져 있다. **사진 영역만 다르다.**

```
글 수정
+-----------------------------------+
| …(등록과 동일한 6개 필드, 값 채워짐)  |
|                                    |
| 사진                               |
|  [img] [img] [img]   <- 현재 3장    |
|  [+ 새 사진 고르기]                 |
|  새 사진을 올리면 기존 사진 3장이     |   <- 인라인 고지
|  모두 교체됩니다. 그대로 두면 유지돼요. |
|                                    |
|  [ ] 사진 3장을 모두 삭제            |
|                                    |
|            [취소]  [저장]           |
+-----------------------------------+
```

- **상태(`status`)는 이 화면에서 바꾸지 않는다.** `[4.6]` 전용 엔드포인트가 따로 있다. 상세에서 바꾼다
- 조회수·등록일·작성자는 바뀌지 않는다. 읽기 전용으로도 두지 않는다 — 수정 화면에 둘 이유가 없다
- 완료(`DONE`) 글도 수정할 수 있다. `[4.6]`의 완료 잠금은 "상태를 되돌릴 수 없다"는 뜻이지 "글을 고칠 수 없다"는 뜻이 아니다

**동작과 결과 고지** — **이 화면의 이미지 규칙은 직관과 어긋난다. 화면이 말해줘야 한다.**

| 사용자 행동 | 서버 동작 | 화면이 알리는 방식 |
|---|---|---|
| 사진을 안 건드림 | 기존 사진 **유지** | 고지 문구 끝에 `"그대로 두면 유지돼요."` |
| 새 사진을 올림 | 기존 사진 **전부 교체** | **인라인** `"새 사진을 올리면 기존 사진 3장이 모두 교체됩니다. 그대로 두면 유지돼요."` — 업로드 버튼 바로 아래 상시 |
| `사진 모두 삭제` 체크 | 기존 사진 **전부 삭제** (`removeImages`) | 체크한 순간 **확인 다이얼로그** |

```
+--------------------------------------+
| 사진 3장을 모두 지울까요?               |
|                                      |
| 저장하면 되돌릴 수 없습니다.            |
|                                      |
|           [취소]  [모두 지우기]        |
+--------------------------------------+
```

- 사진이 0장인 글에서는 교체 고지와 `사진 모두 삭제` 체크박스를 **둘 다 숨긴다.** 알릴 것이 없다
- 새 사진을 고르면 `사진 모두 삭제` 체크박스를 비활성이 아니라 **숨긴다.** 서버는 새 파일을 우선하므로 체크가 의미를 잃는다. 의미 없는 컨트롤을 남기면 사용자가 자기 의도가 반영됐다고 착각한다
- **같은 내용을 두 번 묻지 않는다.** 교체는 인라인 한 번, 전부 삭제는 다이얼로그 한 번이다. 저장 버튼에서 다시 묻지 않는다
- 작성 중 이탈 : `"수정 중인 내용이 있습니다. 나가면 저장되지 않습니다."`

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 기존 값을 불러오는 동안 폼 필드 모양의 스켈레톤. **빈 폼을 먼저 보여주지 않는다** — 사용자가 입력을 시작해버린다 |
| 비어 있음 | 해당 없음 |
| 오류 | 필드별 인라인. 불러오기 실패는 화면 전체를 오류 상태로 |
| 권한 | 작성자가 아니면 **이 화면을 렌더하지 않는다.** 상세로 되돌린다 |

**예외**

| 상황 | 화면 |
|---|---|
| 403 `FORBIDDEN_ACCESS` | 상세로 이동 + `message` |
| 404 `POST_NOT_FOUND` | 목록으로 이동 + `message`. 수정하는 동안 다른 기기에서 지운 경우다 |
| 400 `EXCEEDED_IMAGE_COUNT` | 교체 후에도 5장을 넘으면 서버가 막는다. UI가 먼저 막으므로 도달하면 안 된다 |
| 401 | 인터셉터 재발급 → 실패 시 입력값 보존 후 로그인으로 |

### SCR-05 · 로그인 · `/login`

| 항목 | 내용 |
|---|---|
| **대응** | `[3.2]` 로그인 → `POST /api/auth/login` |
| **권한** | 비로그인. 이미 로그인 상태면 `redirect` 또는 `/`로 보낸다 |

**진입 · 이탈**

| 어디서 들어오나 | 어디로 나가나 |
|---|---|
| 헤더 `[로그인]` · 로그인 필요 화면 진입 차단 · 세션 만료 · 비밀번호 변경 후 | 성공 → `redirect` 쿼리의 경로, 없으면 `/` |
| | `회원가입` → `SCR-06` (`redirect`를 물고 간다) |

**구성 요소**

```
로그인
+-----------------------------------+
| 이메일    [                    ]  |
| 비밀번호  [                 ][보기]|
|                                   |
|          [ 로그인 ]                |
|                                   |
| 아직 계정이 없나요?  회원가입        |
+-----------------------------------+
```

- 비밀번호 보기 토글을 둔다. 불안한 상태에서 한 손으로 입력하다 오타가 나고, **5회 실패하면 30분이 잠긴다**
- 자동완성을 막지 않는다(`autocomplete="email"` / `"current-password"`)

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 제출 중 버튼 잠금 + `"확인 중…"` |
| 비어 있음 | 해당 없음 |
| 오류 | `INVALID_CREDENTIALS` → 폼 하단 인라인. **입력한 이메일은 남긴다** |
| 권한 | 로그인 상태로 들어오면 이 화면을 보여주지 않고 되돌린다 |

**동작과 결과 고지** — 되돌릴 수 없는 동작이 없다.
단 **"5회 실패하면 30분 잠깁니다" 같은 예고를 미리 띄우지 않는다.** 아직 일어나지 않은 일이고, 정상 사용자에게 겁을 준다. 잠긴 뒤에 서버 메시지로 알린다.

**예외**

| 상황 | 화면 |
|---|---|
| 401 `INVALID_CREDENTIALS` | `"이메일 또는 비밀번호가 일치하지 않습니다"` 인라인. 어느 쪽이 틀렸는지 구분해 알리지 않는다 — 계정 존재 여부가 새어나간다 |
| **423 `ACCOUNT_LOCKED`** | 폼 전체를 **잠금 상태**로 바꾼다. 입력과 제출 버튼을 잠그고 `"로그인 5회 실패로 계정이 잠겼습니다 30분 후 다시 시도해주세요"`를 화면 가운데 둔다. 새로고침해도 서버가 다시 423을 주므로 **프론트가 남은 시간을 세지 않는다** |
| 세션 만료로 들어옴 | 폼 위에 `"로그인이 만료됐습니다. 다시 로그인하세요."` |
| 비밀번호 변경 후 들어옴 | 폼 위에 `"비밀번호를 바꿨습니다. 다시 로그인하세요."` |

> **423 잠금 화면은 그 자리에서 스크린샷을 남긴다.** 재현하려면 계정 하나를 5회 실패시키고 30분을 기다려야 한다.

### SCR-06 · 회원가입 · `/signup`

| 항목 | 내용 |
|---|---|
| **대응** | `[3.1]` 회원가입 → `POST /api/auth/signup` |
| **권한** | 비로그인 |

**진입 · 이탈**

| 어디서 들어오나 | 어디로 나가나 |
|---|---|
| `SCR-05`의 `회원가입` 링크 | 성공(201) → `SCR-05` + `"가입했습니다. 로그인하세요."` |
| | 자동 로그인하지 않는다. 가입 응답(`SignupResponse`)에 토큰이 없다 |

**구성 요소**

```
회원가입
+-----------------------------------+
| 이메일    [                    ]  |
| 비밀번호  [                 ][보기]|
| 닉네임    [             ]  0/20   |
|                                   |
|          [ 가입하기 ]              |
+-----------------------------------+
```

- 입력은 셋뿐이다. **비밀번호 확인 필드를 두지 않는다** — 보기 토글이 같은 역할을 하고, 필수 입력을 늘리지 않는 것이 이 서비스의 규칙이다
- 닉네임은 20자(DB `VARCHAR(20)`). 카운터를 둔다
- 이메일·닉네임 중복은 **제출해야 안다.** 실시간 중복확인 엔드포인트가 백엔드에 없다. 임의로 만들지 않는다

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 제출 중 버튼 잠금 |
| 비어 있음 | 해당 없음 |
| 오류 | 필드별 인라인 |
| 권한 | 로그인 상태로 들어오면 `/`로 되돌린다 |

**동작과 결과 고지** — 되돌릴 수 없는 동작이 없다. 다이얼로그를 띄우지 않는다.

**예외**

| 상황 | 화면 |
|---|---|
| 409 `DUPLICATE_EMAIL` | **이메일 필드 아래** `"이미 사용 중인 이메일입니다"` |
| 409 `DUPLICATE_NICKNAME` | **닉네임 필드 아래** `"이미 사용 중인 닉네임입니다"` |
| 400 `INVALID_INPUT` | 해당 필드 아래. 어느 필드인지 모르면 제출 버튼 위 |

### SCR-07 · 내가 쓴 글 · `/me`

| 항목 | 내용 |
|---|---|
| **대응** | `[6.1]` 마이페이지 → `GET /api/members/me/posts?status=&page=&size=` — **백엔드 미구현** |
| **권한** | **로그인 필요.** 비로그인 진입 시 `/login?redirect=/me` |

> **백엔드 미구현.** `MemberController`에 `/me/posts` 매핑이 없다(2026-09-22 확인).
> 화면은 정의해 두고 엔드포인트가 생긴 뒤 붙인다. 응답은 `Page<PostListResponse>` 형태를 전제한다.

**진입 · 이탈**

| 어디서 들어오나 | 어디로 나가나 |
|---|---|
| 헤더 `내 글` | 카드 클릭 → `SCR-03` |
| | `[내 정보]` → `SCR-08` |

**구성 요소**

```
내가 쓴 글
[전체] [게시중] [연락중] [완료]      <- 상태 탭, URL 쿼리스트링
+-----------------------------------+
| +----+ 검은색 반지갑 잃어버렸어요    |
| |썸네일| [분실] (o)게시중            |
| +----+ 강남역 · 9월 20일 · 조회 12  |
|        [게시중][연락중][완료]  [수정] |  <- 소유자 동작
+-----------------------------------+
```

- 카드 정보 위계는 `SCR-01`과 같다. 다만 작성자 닉네임은 뺀다 — 전부 나다. 그 자리에 소유자 동작을 둔다
- **응답 전체가 내 글이므로 `memberId` 비교가 필요 없다.** `PostListResponse`에 `memberId`가 없는 것과 맞물린다
- 상태 탭은 `?status=OPEN` 처럼 URL에 싣는다. 지정하지 않으면 전체다
- **삭제는 여기 두지 않는다. 상세에서만 지운다.** 목록에서 지우면 무엇이 함께 사라지는지(사진·댓글 개수) 다이얼로그에 쓸 근거가 화면에 없다

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 카드 스켈레톤 4개 |
| 비어 있음 (전체 탭) | `"아직 쓴 글이 없습니다."` / `"잃어버렸거나 주운 물건을 올려 보세요."` + `[글 올리기]` |
| 비어 있음 (상태 탭) | `"연락중인 글이 없습니다."` — 탭 이름을 문장에 넣는다 + `[전체 보기]` |
| 오류 | `message` + `[다시 시도]` |
| 권한 | 비로그인은 도달하지 못한다 |

**동작과 결과 고지** — 상태 변경의 규칙과 문구는 `SCR-03`과 **완전히 같다.** 게시중↔연락중은 확인 없이, 완료는 다이얼로그. 화면마다 문구가 다르면 사용자가 같은 경고를 다시 읽어야 한다.

**예외**

| 상황 | 화면 |
|---|---|
| 401 | 인터셉터 재발급 → 실패 시 세션 만료 처리 |
| 409 `INVALID_STATUS_TRANSITION` | 해당 카드 아래 인라인 + 목록 갱신 |
| 404 (엔드포인트 없음) | 백엔드 미구현 구간. 구현 전까지 이 화면은 `"준비 중입니다."` 빈 상태로 둔다 |

### SCR-08 · 내 정보 · `/me/settings`

| 항목 | 내용 |
|---|---|
| **대응** | `[3.7]` 조회 → `GET /api/members/me` · `[3.6]` 닉네임 → `PATCH /api/members/me` · 비밀번호 → `PATCH /api/members/me/password` |
| **권한** | **로그인 필요.** 본인 정보만 다룬다 |

**진입 · 이탈**

| 어디서 들어오나 | 어디로 나가나 |
|---|---|
| 헤더 닉네임 · `SCR-07`의 `[내 정보]` | 닉네임 변경 성공(200) → 이 화면에 머문다 + 헤더 닉네임 즉시 갱신 |
| | 비밀번호 변경 성공(204) → **`SCR-05` 로그인 화면** + `"비밀번호를 바꿨습니다. 다시 로그인하세요."` |

**구성 요소** — 두 폼을 **분리한다.** 저장 버튼이 각각 있다.

```
내 정보
+-----------------------------------+
| 이메일   solmin6320@gmail.com      |   <- 읽기 전용 텍스트
| 가입일   2026-09-01                |
+-----------------------------------+

닉네임 바꾸기
+-----------------------------------+
| 닉네임   [ 김솔민       ]  3/20    |
| 닉네임을 바꾸면 지금까지 쓴 글과      |   <- 인라인 고지
| 댓글의 이름도 함께 바뀝니다.         |
|                       [ 저장 ]     |
+-----------------------------------+

비밀번호 바꾸기
+-----------------------------------+
| 현재 비밀번호 [            ][보기] |
| 새 비밀번호   [            ][보기] |
| 비밀번호를 바꾸면 이 기기를 포함해    |   <- 인라인 고지
| 로그인된 모든 기기에서 로그아웃됩니다. |
|                       [ 저장 ]     |
+-----------------------------------+
```

- **이메일은 읽기 전용 텍스트다.** 입력 필드로 만들지 않는다. 로그인 식별자라 변경 대상에서 빠졌다(`[3.6]`)
- **프로필 사진 영역을 두지 않는다.** `MEMBER` 테이블에 컬럼이 없다. 넣으면 눌러도 아무 일도 안 일어나는 버튼이 생긴다
- 회원 탈퇴 버튼도 두지 않는다. 엔드포인트가 없다

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 이메일·닉네임 자리에 텍스트 스켈레톤. 빈 입력창을 먼저 보여주지 않는다 |
| 비어 있음 | 해당 없음 |
| 오류 | 필드별 인라인 |
| 권한 | 비로그인은 도달하지 못한다 |

**동작과 결과 고지** — 둘 다 **인라인**이다. 되돌릴 수 있는 동작에 다이얼로그를 띄우지 않는다.

| 대상 | 문구 | 위치 |
|---|---|---|
| 닉네임 변경 | `"닉네임을 바꾸면 지금까지 쓴 글과 댓글의 이름도 함께 바뀝니다."` | 닉네임 입력 아래, 저장 버튼 위. 상시 |
| 비밀번호 변경 | `"비밀번호를 바꾸면 이 기기를 포함해 로그인된 모든 기기에서 로그아웃됩니다."` | 새 비밀번호 입력 아래, 저장 버튼 위. 상시 |

- 비밀번호 변경이 전 기기를 로그아웃시키는 건 `MemberService.updatePassword()`가 `refreshTokenService.delete(memberId)`로 리프레시 토큰을 폐기하기 때문이다. **사용자가 예상하지 못하는 결과라 반드시 알린다**
- 204를 받으면 메모리 토큰을 비우고 로그인 화면으로 보낸다. 이미 발급된 액세스 토큰이 최대 5분 살아있지만 **화면은 즉시 로그아웃된 것처럼 동작한다.** 알린 내용과 화면이 어긋나면 안 된다
- 현재와 같은 닉네임으로 저장하면 서버가 200을 준다(멱등). 오류로 다루지 않는다

**예외**

| 상황 | 화면 |
|---|---|
| 409 `DUPLICATE_NICKNAME` | 닉네임 필드 아래 `"이미 사용 중인 닉네임입니다"` |
| **400 `PASSWORD_MISMATCH`** | **"현재 비밀번호" 필드 아래** `"현재 비밀번호가 일치하지 않습니다"`. 400이지 401이 아니다 — **로그아웃시키거나 재발급을 태우면 안 된다** |
| 400 `INVALID_INPUT` | 해당 필드 아래 |
| 401 | 인터셉터 재발급 → 실패 시 세션 만료 처리 |

### SCR-09 · 없는 화면 · `*`

| 항목 | 내용 |
|---|---|
| **대응** | 9장 예외 처리 (`RESOURCE_NOT_FOUND`) |
| **권한** | 비로그인 가능 |
| **진입 · 이탈** | 정의되지 않은 경로 · 오타 · 오래된 링크 → `[목록으로 가기]` |

**구성 요소** — 제목 한 줄, 설명 한 줄, 목록 링크 하나. 그 이상 두지 않는다.

```
없는 화면입니다

목록으로 가기
```

**동작과 결과 고지** — 없다.

**예외** — 없다. 배포에서 `/posts/3` 직접 접근이 이 화면으로 새지 않도록, CloudFront 커스텀 오류 응답(403/404 → `/index.html`, 200)이 앞단에서 처리한다(기능명세서 11장).

## 4. 백엔드 미구현 정리

화면은 정의됐지만 엔드포인트가 없어 지금 붙일 수 없는 것들이다. **프론트에서 임의로 만들지 않는다.**

| 화면 | 기능 | 필요한 것 | 영향 |
|---|---|---|---|
| `SCR-07` | `[6.1]` 마이페이지 | `GET /api/members/me/posts` | 화면 전체가 동작하지 않는다 |
| `SCR-03` | `[5.1]` 댓글 등록 | `POST /api/posts/{id}/comments` | 댓글 읽기만 되고 쓸 수 없다 |
| `SCR-03` | `[5.1]` 댓글 수정·삭제 | `PUT`·`DELETE /api/comments/{id}` · `COMMENT_NOT_FOUND` ErrorCode | 소유자 동작이 없다 |
| `SCR-03` | `[5.1]` 댓글 더 보기 | `GET /api/posts/{id}/comments?page=` | 20건을 넘으면 더 볼 수 없다 |

의도적으로 **만들지 않은** 화면 — 백엔드에 없고 명세서에도 없다.

| | 이유 |
|---|---|
| 이메일 변경 | 로그인 식별자라 변경 대상에서 제외(`[3.6]`) |
| 프로필 사진 | `MEMBER` 테이블에 컬럼이 없다. DB 명세서 7장 확장성에 10/20 배포 이후 항목으로 올라 있다 |
| 회원 탈퇴 · 비밀번호 찾기 · 게시글 신고 | 명세서에 없다 |

프론트 구현에 영향을 주는 백엔드 사실 두 가지.

- `LoginResponse`에 회원 식별자가 없다(`accessToken` `tokenType` `accessTokenExpires`). 로그인 직후 `GET /api/members/me`를 한 번 더 호출해야 작성자 판정과 헤더 닉네임 표시가 가능하다
- 리프레시 쿠키의 `secure(true)`가 `AuthService`에 하드코딩돼 있다. 브라우저에 따라 로컬 개발에서 쿠키가 저장되지 않아 `[3.3]` 재발급이 막힐 수 있다(기능명세서 8장이 이미 지적한 항목)

## 5. 스크린샷 체크리스트

이 프로젝트는 백엔드 포트폴리오이고, 프론트는 "찍을 화면이 없다"는 약점을 메우는 수단이다.
**조건을 다시 만들기 어려운 화면은 만든 그 자리에서 찍는다.**

| 화면 | 만드는 법 | 재현 난이도 |
|---|---|---|
| `SCR-05` 423 계정 잠금 | 로그인 5회 실패. 풀리는 데 30분 | **가장 어렵다** |
| `SCR-03` 409 상태 전이 거부 | 완료 글에 상태 변경 요청(도구로 직접) | 어려움 |
| `SCR-03` 삭제 확인 다이얼로그 | 사진·댓글이 모두 있는 글에서 `[삭제]` | 숫자가 들어간 문구를 찍으려면 데이터 준비 필요 |
| `SCR-01` 완료 글 흐림 처리 | 완료 글이 섞인 목록 | 데이터 준비 필요 |
| `SCR-01` 사진 섞인 피드 | 목록 썸네일(`thumbnailUrl`) 머지 후, 사진 있는 글 · 없는 글이 섞인 목록 | 백엔드 머지 대기 |
| `SCR-02` 이미지 6장 차단 | 파일 6개 선택 | 쉬움 |
| `SCR-04` 사진 전부 삭제 확인 | 사진 있는 글에서 체크박스 | 쉬움 |
| 각 화면 로딩 스켈레톤 | 네트워크 스로틀링(Slow 3G) | 쉬움 |
| 각 화면 비어 있음 | 없는 키워드로 검색 | 쉬움 |
